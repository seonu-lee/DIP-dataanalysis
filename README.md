# Soundscape_DIP: LLM 기반 상황 인식 음악 추천 시스템

> 사용자의 현재 위치, 활동 목적, 주변 소음(dB) 등 다차원적인 상황 맥락을 LLM이 해석해, 최적화된 음악 특성을 매칭하고 개인화된 플레이리스트를 제공하는 시스템의 **데이터 분석 및 검증 레포**입니다.

---

## 프로젝트 배경 & 담당 역할

TAVE 연합 동아리 팀 프로젝트로, 백엔드·프론트엔드·디자인·PM으로 구성된 팀에서 **데이터 분석가는 본인 혼자**였습니다.

- KPI 체계 설계 (8개 후보 지표 중 측정 가능하고 신뢰할 수 있는 4개 지표 선정)
- 사전배포 직접 제안 및 로그 스키마 정의 (팀 원안에 없던 단계)
- 실사용자 로그(18명, 약 300건) 분석 및 인사이트 도출
---

## 프로젝트 구조 및 상세 분석 내용

### 1. EDA & 데이터 전처리 (`/EDA`)

- **환경 소음 데이터**: 한국환경공단 측정망 데이터를 활용해 5단계 소음 구간(Noise Band) 정의
  - Very Quiet(0~35dB) ~ Very Loud(81dB+) 구간별 맞춤형 추천 로직 설계
- **사용자 맥락 데이터(RAED)**: 위치(Library, Home 등), 행동(Studying, Walking 등) 데이터를 구조화해 상황별 페르소나 생성
- **음악 특성 프로파일링**: Spotify API의 정량 지표(Energy, Valence, Tempo 등)를 활용해 상황-음악 매칭 매트릭스 구축
  - 예: 집중 필요 시 → 낮은 Energy, 높은 Instrumentalness 추천

### 2. 성능 평가 (`/성능평가(KPI)`)

정답 레이블이 없는 LLM 기반 추천에서 "정확도"를 어떻게 정의할지부터 고민이 필요했습니다. 8개 후보 지표 중 API 제약과 측정 가능성을 기준으로 4개 지표를 선정해 실제 로그로 검증했습니다.

| 지표 | 결과 | 의미 |
|---|---|---|
| Context-Sentiment Accuracy | 81.17% | 입력 상황(위치, 목표)이 추천 사유에 정확히 반영되었는가 |
| Persona-Genre Accuracy | 100.00% | 사용자 취향이 페르소나 요약·장르 선정에 반영되었는가 |
| Agent Latency | 평균 7.62초 (중앙값 6.34초) | 응답 속도의 안정성 |
| Deep Link Conversion (DLC) | 85.15% | 추천 결과에 대한 실제 Spotify 이동 클릭률 — 설문이 아닌 실제 행동 기반 수용도 |

> 지표 하나하나가 측정하기 쉬운 것과 실제로 중요한 것이 항상 일치하지는 않았습니다. 예컨대 Persona-Genre Accuracy는 기준이 관대해 100%가 나왔지만, DLC는 사용자의 실제 클릭 행동을 반영한다는 점에서 가장 신뢰할 수 있는 지표로 판단했습니다.

### 3. 통계 및 로그 분석 (`/통계분석`)

사전배포 기간(18명, 약 300건) 수집된 실사용자 로그를 기반으로 패턴을 분석했습니다.

- **주요 사용 맥락**: '집', '코워킹 스페이스', '이동 중' 환경에서 '집중'과 '휴식' 목적의 사용이 주를 이룸
- **위치×목표 조합**: 카페-집중, 집-휴식/수면 등 특정 장소와 활동 간 명확한 결합 패턴 도출
- **유저 세그먼트**: 리텐션 데이터를 기반으로 '충성파(Loyal)'와 '중성파'로 분류
- **이탈 유저 개별 분석**: 이탈 2건을 각각 들여다본 결과, 원인이 취향 미스매치와 응답 지연으로 서로 다르다는 걸 시계열로 구분 → 개인화 기능 도입 시 응답속도 모니터링을 강화하는 방향으로 팀 우선순위에 반영됨

## 기술 스택

- **Language**: Python (Jupyter Notebook)
- **Libraries**: Pandas, NumPy, Matplotlib, Seaborn, Scipy
- **LLM Strategy**: Prompt Engineering & Context Construction
- **Data Sources**: 한국환경공단(소음), Spotify API, RAED Dataset

---

## 실행 가이드

1. **데이터 탐색**: `EDA/` 폴더 노트북에서 소음 데이터와 음악 특성이 어떻게 연계되는지 확인
2. **성능 확인**: `성능평가(KPI)/`에서 실제 모델의 정확도와 사용자 반응 지표 확인
3. **인사이트 확인**: `통계분석/` 폴더에서 실제 유저들이 어떤 상황에서 음악 추천을 선호했는지 분석 결과 확인

---

## 분석의 한계

- 표본이 18명으로 작아, 발견한 패턴은 통계적 유의성보다는 방향성 힌트로 해석했습니다.
- Latency는 특정 구간에서 급등이 관측되어, 기능 도입 시점과의 연관성을 시계열로 함께 확인했습니다.
- 정답 레이블이 없는 구조 특성상, Context-Sentiment Accuracy는 키워드 매칭 기반이라는 한계가 있습니다.

---

## 기대 효과

이 시스템은 단순한 장르 추천을 넘어 **"현재 카페의 소음이 65dB인 상태에서 집중을 원하는 사용자"**에게 가장 과학적으로 적합한 음악을 추천함으로써, 사용자의 생산성 향상과 심리적 안정에 기여합니다.
